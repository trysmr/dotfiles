# Handoff

新しいセッションが会話履歴なしでも迷わず再開できる、自己完結したプロンプトを作る。ファイルには保存せず、会話へコードブロックで提示する。

## Workflow

1. 対象リポジトリの規則を読み、Git情報の確認が許可されているか判断する。
   - 許可されている場合だけ、必要な範囲で`git branch --show-current`、`git status --short --untracked-files=all`、`git diff --stat`、`git log --oneline -5`を実行する。
   - 禁止されている場合や許可が不明な場合はGitコマンドを実行しない。会話と実行済み出力からまとめ、確認できない項目へ「未確認」と理由を書く。
   - `.env`、`.git/`、対象リポジトリで無視されるファイルは読まない。
2. 会話と実行済み出力から、次の事実を集める。
   - ユーザーが明示したゴール、制約、方針
   - 確定した判断とその理由
   - 会話内で管理しているCodexのplanまたはtodoの各項目と状態
   - 変更したファイルと各変更の意図
   - 実行した検証コマンドと結果
   - 失敗したアプローチ、原因、再試行すべきでない条件
   - 未確認の仮説と検証できていない範囲
3. planまたはtodoは外部ファイルへの参照に置き換えず、現在の状態を引き継ぎ本文へ直接展開する。
4. 以下のテンプレートでプロンプトを組み立てる。該当情報がない項目は「なし」と書き、確認できない項目は省略せず「未確認」と書く。

````markdown
# 引き継ぎ: <タスク名>

前セッションからの引き継ぎです。以下を読んで作業を再開してください。

## ゴールと制約
<達成する内容、ユーザーが指定した制約と方針>

## 確定した判断
<判断、その理由、新しいセッションで維持すべき前提>

## 現在の状態
- Git情報の確認: <確認済み、または未確認と理由>
- ブランチ: <確認済みの名前、または未確認>
- コミット状況: <確認済みの状態、または未確認>
- 変更したファイル:
  - `<絶対パスまたはリポジトリルートからの相対パス>`: <変更の意図>

## Plan/Todo
- [x] <完了した項目>
- [ ] <進行中または未完了の項目>

## 試して失敗したこと
<アプローチ、失敗理由、再試行を避ける条件。なければ「なし」>

## 検証
- `<実行したコマンド>`: <結果>
- 未確認: <実行できなかった検証と理由>

## 次の一手
<再開後に最初に着手する1つの作業>
````

5. 内容を自己検証する。
   - 「さっきの」「例の」「上記の通り」など、会話に依存する語を具体的な名前とパスへ置き換える。
   - パスは絶対パスかリポジトリルートからの相対パスにする。
   - 相対日付は絶対日付へ直す。
   - 確認済みの事実、推測、未確認事項を区別する。
   - 検証は一般名でなく、実行したコマンドと結果を書く。
   - 同じ袋小路を避けるため、失敗の記録を残す。
6. コードブロックの後に、新しいセッションへそのまま貼り付ければ使えることと、漏れがないか確認してほしいことを1文で添える。
