# Handoff

新しいセッションが次の作業を迷わず始められる、短いプロンプトを会話へコードブロックで提示する。ファイルには保存しない。

## Workflow

1. 会話と実行済み出力から、再開に必要な事実だけを抽出する。
   - ゴールとユーザーが指定した制約
   - 作業中の項目と次の一手
   - 次の作業へ影響する判断、変更ファイル、検証結果
   - 再試行を避けるべき失敗、未確認事項
2. Git情報は既知の内容を優先する。現在の作業状態が不明で、再開に必要な場合だけ、リポジトリの規則が許す範囲でブランチとstatusを確認する。履歴やdiffの要約は必要性が明確な場合に限る。`.env`、`.git/`、無視されるファイルは読まない。
3. 通常版は本文800字以内を目安にする。複雑な作業でも1,200字を超えない。ユーザーが「詳細に」と指定した場合だけ、この上限を外してよい。
4. 次の情報は省く。
   - 完了した作業の経緯や、次の作業へ影響しない変更
   - 「なし」だけになる項目、確認する必要がないGit情報
   - 会話の要約、同じ事実の言い換え、定型の前置きと後書き
   - コマンドの全履歴。再開判断に使う代表的な検証結果だけ残す
5. 以下を基本形にする。不要な行や節は削り、項目を埋めるための推測はしない。

````markdown
# 引き継ぎ: <タスク名>

## 目的
<ゴールと維持すべき制約を1〜2文>

## 現在地
- 作業中: <現在の状態>
- 変更: `<パス>` — <次の作業に必要な変更意図>
- 検証: `<コマンド>` — <結果>

## 次にやること
1. <再開後に最初に行う具体的な作業>

## 注意
- <維持すべき判断、避ける失敗、未確認事項のいずれか>
````

6. 提示前に、会話依存の表現を具体的な名前やパスへ直し、確認済みの事実と未確認事項を区別する。情報量ではなく、新しいセッションが最初の一手を正しく選べるかで判断する。
