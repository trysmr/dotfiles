# Japanese Check

日本語の成果物を機械チェックとニュアンスチェックの2段階で確認し、修正する。判断基準は対象リポジトリの規則を優先し、共通規則は`.codex/AGENTS.md`のLanguage Standardsを定義元とする。

## Workflow

1. 依頼から対象を決める。
   - 指定ファイルは、そのパスをスクリプトへ渡す。
   - ドラフトは、標準入力でスクリプトへ渡す。
   - 変更差分は、対象リポジトリの規則がGit情報の確認を許可している場合だけGitで対象ファイルを特定する。許可されない場合は、会話と実行済み出力から対象を特定し、未確認の範囲を明示する。
   - `.env`、`.git/`、対象リポジトリで無視されるファイルは読まない。
2. バンドルスクリプトで定型違反の候補を検出する。

```bash
# ファイル
python3 <スキルディレクトリ>/scripts/check_japanese.py <ファイルパス...>

# ドラフト
python3 <スキルディレクトリ>/scripts/check_japanese.py <<'EOF'
<ドラフト本文>
EOF
```

3. 検出箇所の文脈を読み、誤検知を除く。引用文、規則の説明、正規表現リテラルなど、意図的な表現は書き換えずに報告する。
4. 声に出して自然かという観点で、機械判定できない表現も確認する。
   - 漢語接頭辞を使った不自然な造語を、条件を説明する文へ開く。
   - 助詞を省いた複合名詞を、自然な句や文へ直す。
   - 英語の直訳調、丁寧形が混ざったコミットタイトル、識別子を詰め込んだ説明を直す。
   - コミットやPRでは、レビュープロセスではなく変更が必要な理由を書く。
   - 既存用語か迷う場合は、機密情報と無視対象を避け、対象リポジトリの規則で許可された方法だけで確認する。
5. ファイルは文脈を保って修正し、ドラフトは修正済み本文を提示する。
6. 修正後の対象へスクリプトを再実行し、残る候補を確認する。

手動スクリプトは成果物全体から候補を広く検出し、フックは実行時に高い精度で判定できる規則だけを扱う。そのため、検出範囲は完全には一致しない。パターンを変更するときは`.codex/hooks/japanese_commit_check.py`と`.codex/hooks/japanese_write_check.py`への影響を確認し、対応するテストも更新する。候補がゼロでも、ニュアンスチェックは省略しない。

## Report

```text
日本語チェック:
- 機械チェック: N件検出 -> M件修正、K件は意図的な表現のため保留
- ニュアンス: <修正内容。なければ「問題なし」>
- 再実行: <定型違反なし、または残る候補と理由>
```
