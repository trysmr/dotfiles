# Handoff

新しいセッションは会話履歴・思考過程・途中の試行錯誤を一切持ちません。このスキルの目的は、コピペ1回で新セッションが迷わず作業を再開できる自己完結したプロンプトを作ることです。

## Step 1: 事実の収集

記憶だけに頼らず、現在の状態をコマンドで確認します:

```bash
git branch --show-current && git status --short && git diff --stat
git log --oneline -5
```

加えて以下を会話から整理します:

- ユーザーが明示した目標・制約・設計判断（判断の理由も）
- todoリストの状態（あれば）
- 対応するplanファイル（`~/.claude/plans/*.md`にあれば、そのパス）
- 試して失敗したアプローチとその原因

## Step 2: 引き継ぎプロンプトの生成

以下のテンプレートで組み立て、**会話にコードブロックで表示**します（ファイルには保存しません。ユーザーがそのまま新セッションに貼り付けます）:

````markdown
# 引き継ぎ: <タスク名>

前セッションからの引き継ぎです。以下を読んで作業を再開してください。

## ゴールと制約
<何を達成したいか。ユーザーが指定した制約・方針>

## 設計判断（確定事項）
<ユーザーが決めた判断とその理由。新セッションで蒸し返さないため>

## 現在の状態
- ブランチ: <ブランチ名>
- 変更済みファイル:
  - `<絶対パス>` — <変更の意図>
- コミット状況: <未コミット差分の有無、直近コミット>

## 未完了タスク
- [ ] <残作業を具体的に>

## 試して失敗したこと
<失敗したアプローチと原因。再試行を避けるため。なければ省略>

## 検証方法
<実際に実行したlint/テストコマンドをそのまま>

## 次の一手
<最初に着手すべき1つの作業>
````

## 書き方の原則

- **会話依存の語を使わない**: 「さっきの」「例の」「上記の通り」は新セッションでは無意味。名前とパスで指す
- **パスは絶対パスかリポジトリルートからの相対パス**で書く
- **相対日付は絶対日付に変換**する（「昨日」-> 「2026-07-13」）
- **確認済み事実と推測を区別**する。未検証の仮説は「未確認:」を付けて書く
- **コマンドは実物を書く**。「テストを実行」ではなく実行したコマンドそのもの
- **失敗の記録を省かない**。新セッションが同じ袋小路に入るのが引き継ぎ最大の失敗
- planファイルがある場合はテンプレート全体を膨らませず、パスを示して「まずこれを読む」と書く

## Step 3: 提示

コードブロックの後に1行だけ添えます: 使い方（新セッションに貼り付けるだけ）と、引き継ぎ内容に漏れがないかの確認依頼。
