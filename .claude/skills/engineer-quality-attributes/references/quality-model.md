# 品質モデル

ISO/IEC 25010:2023の製品品質とISO/IEC 25019:2023の利用時品質を、漏れを防ぐ確認枠として使う。規格の認証や正式な適合確認が必要な場合は、正規の規格本文と組織の手順を優先する。

## 製品品質と利用時品質を分ける

- 製品品質では、ICT製品やソフトウェアが備える性質を評価する。
- 利用時品質では、明示した利用状況で利害関係者が得る便益、被るリスク、受け入れ方を評価する。
- 製品品質の良さだけから利用時品質を推定しない。実際の利用者、業務、設備、周辺サービス、社会的影響を含む利用状況を別に確認する。
- 1つの事象が両方に関係する場合も、評価面を分ける。例として、画面の誤操作防止は製品品質、実業務での誤処理件数は利用時品質として扱う。

## 製品品質の9特性

すべてを`適用する`、`対象外`、`判断待ち`のいずれかに分類し、理由と確認した情報を残す。

| 特性 | 下位特性 | 主な焦点 |
|---|---|---|
| 機能適合性 | 機能完全性、機能正確性、機能適切性 | 必要な機能が揃い、正しい結果を出し、目的達成に役立つか |
| 性能効率性 | 時間効率性、資源効率性、容量満足性 | 所要時間、処理量、資源使用量、上限が利用条件に合うか |
| 互換性 | 共存性、相互運用性 | 同じ環境で他製品を妨げず、必要な情報交換ができるか |
| インタラクション能力 | 適切度認識性、習得性、操作性、利用者の誤り防止、利用者関与性、包摂性、利用者支援性、自己記述性 | 利用者が目的と操作を理解し、学び、誤りを避け、必要な支援を得られるか |
| 信頼性 | 無欠陥性、可用性、耐障害性、回復性 | 必要な期間に機能し、障害を抑え、継続または復旧できるか |
| セキュリティ | 機密性、完全性、否認防止、責任追跡性、真正性、攻撃耐性 | 情報と機能を適切な主体に限定し、改変や攻撃へ対処し、行為を追跡できるか |
| 保守性 | モジュール性、再利用性、解析性、変更性、テスト容易性 | 影響を把握し、局所的かつ安全に変更して確認できるか |
| 柔軟性 | 適応性、拡張性、設置性、置換性 | 環境、負荷、構成、部品の変更へ追従できるか |
| 安全性 | 運用制約、リスク識別、フェイルセーフ、危険警告、安全な統合 | 人、財産、組織、環境への許容できない危害を避けるか |

## 各特性の確認観点

### 機能適合性

- 業務上必要な機能、例外処理、権限別の振る舞いが揃っているか。
- 計算、状態遷移、集計、外部連携の結果を何と照合できるか。
- 機能が存在しても、利用者の目的達成を遠回りにしていないか。
- 受入条件、業務例、照合用データ、回帰テストはあるか。

### 性能効率性

- どの操作、利用者数、データ量、時間帯を対象にするか。
- 平均値だけでなく、分位点、最大値、処理量、待ち時間のどれが重要か。
- CPU、メモリ、接続数、ストレージ、外部サービス上限を観測できるか。
- 通常時、繁忙時、劣化時の条件と許容範囲を誰が決めるか。

### 互換性

- 共存するアプリ、ライブラリ、ブラウザ、OS、ネットワークへ悪影響を与えないか。
- 情報形式、プロトコル、時刻、文字コード、再試行、エラー処理が接続先と一致するか。
- 接続設定の存在だけでなく、代表的な連携を実行して結果を確認しているか。
- 相手側の変更や一時停止へどう追従するか。

### インタラクション能力

- 対象利用者が機能の目的、現在状態、次の操作を理解できるか。
- 初回利用、頻繁な利用、支援技術の利用で操作を完了できるか。
- 破壊的操作、入力誤り、二重送信を予防し、回復方法を示せるか。
- 表示、文言、キーボード操作、読み上げ、色、拡大への対応を実際に評価したか。
- ヘルプ、入力例、進行状況、エラー内容が利用者の判断を支えるか。

### 信頼性

- 必要な稼働時間と停止時の影響を明示しているか。
- 単一障害点、依存先障害、部分障害、データ不整合を想定しているか。
- 再試行、冗長化、縮退、隔離、バックアップがどの失敗へ効くか。
- 復旧手順を実行し、復旧時間と失われるデータ量を測定したか。

### セキュリティ

- データ、操作、主体ごとに閲覧・変更・実行できる範囲が明確か。
- 保存時と通信時の保護、入力検証、セッション管理、依存物管理があるか。
- 誰が何を行ったかを改ざんされにくい形で追跡できるか。
- なりすまし、権限昇格、入力攻撃、資源枯渇、供給網攻撃を検証したか。
- 詳細な確認が必要なら`security-reviewer`へつなぐ。

### 保守性

- 変更理由が異なる責務を分離し、依存方向を把握できるか。
- 同じ知識を複数箇所へ重複させず、局所的に変更できるか。
- ログ、トレース、エラー、命名から原因と影響を解析できるか。
- 自動テストで主要な分岐、失敗、公開インターフェースを確認できるか。
- 詳細な設計判断は`design-principles`、保守性の問題探索は`code-smell`へつなぐ。

### 柔軟性

- 対応環境、構成差、負荷増加、データ量増加を明示しているか。
- 拡張時にどの資源や外部制限が先に上限へ達するか。
- 導入、更新、戻し、データ移行を再現できるか。
- 部品や外部サービスを置き換える境界、形式、移行手順があるか。

### 安全性

- 人命、健康、財産、組織活動、環境へ生じ得る危害を列挙したか。
- 許容範囲外の操作や状態を検知し、停止または安全な状態へ移れるか。
- 警告が対象者へ間に合い、意味と対応方法が伝わるか。
- 他システムとの組み合わせで新たな危害を生まないか。
- セキュリティ上の攻撃、信頼性上の故障、安全性上の危害を同一視せず、因果関係を示す。

## 対象外にする条件

`対象外`は「考えなくてよい」の別名にしない。次をすべて満たす場合に限って候補にする。

1. 評価対象の境界、利用者、環境、ライフサイクル段階を明示する。
2. その境界では該当する機能、連携、操作、危害、変更が存在しないことを確認する。
3. 対象外にした理由と、判断に使った資料または担当者を記録する。
4. 境界や利用状況が変わった場合に再評価する条件を記録する。

判断材料が足りない場合は`判断待ち`にする。根拠がないまま`対象外`にしない。

## 利用時品質

ISO/IEC 25019:2023は利用時品質を3特性で扱う。製品品質の9特性とは別表にする。

| 特性 | 確認する内容 | 代表的な確認方法 |
|---|---|---|
| 有益性（Beneficialness） | 指定した利用状況で、利用者や組織が目的を達成し、必要な便益を得られるか | 業務結果、タスク完了、所要時間、利用者評価、アクセシビリティ評価 |
| リスクからの保護（Freedom from risk） | 経済、人命・健康、社会・倫理、環境への悪影響を十分に抑えられるか | リスク分析、事故・損失記録、実地訓練、監査、利害関係者による評価 |
| 受容性（Acceptability） | 利用者、顧客、責任を持つ組織、社会が体験、信頼、規則への適合を受け入れられるか | 利用者調査、苦情、継続利用、説明の理解、規則への適合確認 |

次を先に明示する。

- 利用者、顧客、運用者、責任を持つ組織、影響を受ける社会集団
- 物理環境、端末、支援、時間制約、通常時と例外時
- 達成する目的と、望ましくない結果
- 評価期間、対象母集団、収集方法

利用状況が変わった場合は評価条件を定義し直す。製品側の設定やテストだけで利用時品質を満たすとは判断しない。

## 2011年版からの主な変更

- 製品品質と利用時品質を分け、利用時品質をISO/IEC 25019:2023へ移した。
- 製品品質を8特性から9特性へ増やし、安全性を追加した。
- 使用性をインタラクション能力へ、移植性を柔軟性へ変更した。
- インタラクション能力へ包摂性、利用者支援性、自己記述性などを加えた。
- 信頼性の成熟性を無欠陥性へ、利用者インターフェースの美しさを利用者関与性へ見直した。
- セキュリティへ攻撃耐性、柔軟性へ拡張性を加えた。

この一覧は実務で版の取り違えを防ぐための要約であり、差分の完全な転載ではない。
