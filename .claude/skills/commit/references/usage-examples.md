# コミットの使用例

形式はA・B・Cの優先順ではなく、確認できた変更理由を伝えるために選ぶ。ファイル数や文数では決めない。本文は1段落1行とする。

## 本文で理由を補う例

```bash
git commit -m 'ECSデプロイ処理をBuildからDeployステージに変更' -m '標準のECS Deployアクションを使い、BuildとDeployの責務を分ける方針とした。Buildからサービスの更新を外し、Deployで実行する構成に変更した。'
```

運用方針が理由であり、確認していない障害を作らない。

## タイトルだけで理由まで伝わる例

```bash
git commit -m '日付経過で期限切れになる開発seedをCURRENT_DATE基準に変更'
```

## 複数の要点が必要な場合

理由と箇条書きを含む本文をWriteで一時ファイルへ書き、`git commit -F <本文ファイルの絶対パス>`で渡す。本文をコマンド置換へ埋め込まない。

「応答を修正」「応答形式に変更した」の組み合わせでは理由がない。なぜ必要かを確認して補う。単に本文を省いたり、2文へ増やしたりして解決したとしない。
